# 014 方法与数据研究：先把 27B 的推理能力变成可选的真实答案

查阅日期：2026-10-17（北京时间）。本文件是方法子研究，供本轮主计划整合；不是新增 GPU 配额承诺。只读本地 007–013 记录、一手论文、作者源码与小文件网页。本轮没有训练、模型推理、GPU 作业、权重大下载、比赛提交或外部消息；以下新实验全部**未运行**。最新榜单、013 比赛分数与正式运行归因由本轮提交审计另行负责，本文件不猜隐藏运行日志。

## 1. 建议只保留三个问题

1. **第一优先：原 Qwen3.8-27B 在可并发的推理引擎上，足够完成的思考能否带来开发题新解？** 现有 0/14 主要检验了 nonthinking 直接网格小适配配置；程序 4/4 耗尽 3072 token 尚未检验真正的程序执行反馈。先修复实验的能力与成本覆盖，再判断底座。
2. **第二优先：程序验证或独立思考产生的答案，能否在真实两个提交槽中替换掉无效候选，取得净新增？** 评价必须同时看原方案丢掉的解；不能用候选并集替代最终选 2。
3. **第三优先、满足条件才训练：训练目标应转为可验证、短的规则实现，并优先增加独立实例，而非继续同一小池网格答案的 25→50→100 步。** 先用 CPU 形成小而可信的数据，再决定是否值得花本周 GPU。不是现在开启 30K/百万条重训。

TTT 和长思考竞争同一运行预算。当前没有理由给 27B 所有隐藏题都加 TTT；已有 4B 专项基线的题内适配则属于已经运行过的另一条路线，不能把二者混为同一结论。主模型选择保持 Qwen3.8-27B，SOAR 不进入候选或论证。

## 3. 外部证据：哪些已有可用资产，哪些不值得本周照搬

### 3.1 同一个 27B：首先测推理配置，不重开模型选型

ARC Prize 官方结果仍列该 27B 的 ARC2 Semi-Private：xhigh 42.4%、low 22.8%、medium 13.2%、none 1.5%。官方同时说明 low/xhigh 在模板中加入不同指令，而 medium 没有相应指令；它不是单一“token 越多越好”的实验，结果也不是 Kaggle 分数。官方运行使用 Baseten 专用推理，不能承诺 4×L4 原样复现其预算。[官方结果](https://arcprize.org/results/alibaba-qwen3-8-27b)

本项目已有官方 BF16 权重、固定模板和第三方 FP8/wheelhouse 的 CPU 身份核对，013 已审过 TP4/并发实现。权重张量数值等价、依赖兼容、L4 吞吐仍未确认。不要继续拿 `device_map=balanced` 的串行速度作为 27B 最终预算结论。[013依赖记录](../013/qwen-public/dependency-readiness.md)、[013公开代码审阅](../013/qwen-public/AUDIT.md)、[官方模型卡](https://huggingface.co/Qwen/Qwen3.8-27B)

研究动作：保留原模型，先恢复它已有的思考能力；不要同时添加新 SFT、TTT、词表裁剪与提示搜索，否则即使有改善也无法判断哪个改变有用。

### 3.2 NVARC：独立规则组合有资产，但训练规模不能伪装成小试验

作者公开 103K 合成 puzzle、3.2M 增强 puzzle、生成流水线、4B 训练与提交实现。`run_sft_4b.sh` 明确是 4 节点、TP8、global batch256、最高12716更新；旧论文训练投入为32×H100、27小时。它支持借鉴组合规则和验证过程，不支持把本项目几百样本 LoRA 看成等价复现。[作者仓库](https://github.com/1ytic/NVARC)、[实际训练脚本](https://raw.githubusercontent.com/1ytic/NVARC/main/ARChitects/run_sft_4b.sh)

本周最有价值的是读取少量来源明确的生成程序、验证独立实例和目标实现；不下载所有增强、不重建作者集群训练、不把使用了 evaluation 规则衍生材料的结果称为未见规则泛化。

### 3.3 ARC-TGI：可执行规则与实例模板已有；收益仍需自己验证

作者提供 461 个生成器，包含 ARC2 的55个 train 与11个 eval 来源，配有规则文本和部分求值后的 Python。它特别处理同一 episode 的示例能否展示必要的变化。论文微调中 Qwen3-8B 的同族数据结果下降，外部分布没有稳定改善，不能把“人工审过、含推理链”当收益保证。[论文](https://arxiv.org/html/2603.05099v1)、[作者生成器](https://github.com/Omega-Reasoning/ARC-Task-Generators-Inventory)

本项目已经有 ARC-GEN 的448族新 base 和009消歧工作，优先审自己的现成数据；TGI 用来补确实缺失的 training-only 规则实现。默认遍历会包含 Eval 目录，不能整库直接物化进训练池。代码与规则文本的许可/来源需随样本保存；论文许可与代码仓库许可分开。

### 3.4 DiARC：有现成 4B adapter，值得审，不是27B的新答案

2026年6月的 DiARC 在 NVARC 式专项 Qwen3-4B 上增加偏好学习。论文 ARC2 公开评估任务均值 hit@2 为30.83→33.06；这是作者原始task宏平均口径，不能换算为本比赛按query平均的主指标。数据来自 NVARC-full，故保留公开规则衍生材料与训练污染口径。作者未报告本项目27B的收益。[论文](https://arxiv.org/html/2606.26530v1)

资产核实：作者代码包含负样本构造、DPO、推理工具，HF manifest 中 `qwen3-4b/arc-agi-2` 有2,119,438,568字节 adapter，选择项为 rigid shift，基座标识 `qwen3_4b_grids15_sft139_bfloat16`。33.06明确来自公开 evaluation 的本地 `submission.json` 评分，**不是 Kaggle 公榜**。本次未下载权重，也未取得该叶目录 adapter_config；manifest 标记的基座不是已验证的二进制匹配。[源码](https://github.com/szu-tera/DiARC)、[权重清单](https://huggingface.co/yyxdnmd/DiARC-adapters/blob/main/manifest.json)、[资产说明](https://raw.githubusercontent.com/szu-tera/DiARC/main/docs/artifact_notes.md)

实际 DPO 代码默认 r256、4096上下文、batch2×accum4、1epoch、lr1e-6，并对 embed/head 做 LoRA；论文用单 L40。27B与当前推理栈的移植代价、显存和运行时间均未确认，不能据此承诺一晚训练完。对现有4B基线，可先做CPU基座/词表/adapter键审计，再考虑独立小对照；这不是换掉27B主线，更不能直接把4B adapter挂到27B。[训练入口](https://raw.githubusercontent.com/szu-tera/DiARC/main/src/diarc/train_dpo_qwen.py)

### 3.5 程序执行：有完整开源机制，需剥离大模型与多轮预算

Poetiq 提供可读执行反馈与候选投票实现，但默认 Gemini 配置最多10轮、最多5个解，API超时1小时；它不是可直接在Kaggle离线运行的高分权重。[作者仓库](https://github.com/poetiq-ai/poetiq-arc-agi-solver)、[实际配置](https://raw.githubusercontent.com/poetiq-ai/poetiq-arc-agi-solver/main/arc_agi/config.py)

2026年的 agentic coding 作者实验给出 ARC2 public eval 的 GPT-OSS-120B 6.11→26.38（CoT→REPL），并开放源码和实验记录；这里有“执行比纯文本思考有用”的相关证据，但模型、预算、工具实现均不同，不能移植效应量。代码依赖 stateful REPL 与正确的 interleaved thinking；只把 shell 接口加上而丢弃思考状态，并不复现这个机制。[作者报告](https://pivotools.github.io/pivotools-quarto-blog/posts/agentic_coding_arc_agi/)、[作者代码](https://github.com/gutfeeling/arc-agi-2-submission)

本周只复用已经有的 `transform(grid)` 执行器和一次反馈；不开发通用多agent环境。不让模型看到query金标准，演示全对也不保证泛化。

### 3.6 最新压缩与搜索：作为窄假设，不启动新框架

Hourglass（2026-07）有作者代码：通过规则/表示的中间状态隔离推理阶段。论文使用GPT-5.5与Gemini3.1 Pro，主结果best-of-5，约多消耗2–3倍token，明确不是等算力比较。所谓压缩是跨阶段信息约束，不是已证实的低token推理。可借“先形成简短规则、再输出完整程序”的设计；不运行其32/60次候选配置。[论文](https://arxiv.org/html/2607.11696v1)、[作者实现](https://github.com/ZhuHuan09/hourglass-reasoning)

LLM+遗传搜索（2026-09）在公开ARC2前60题从LLM初始2题增到6题，使用专门41操作DSL、GPU种群搜索，每题最高600秒。它提示程序候选可局部改进，但需要新DSL/GPU执行器；本周不重写这套系统，报告也不是完整120题或Kaggle成绩。[作者论文](https://arxiv.org/html/2609.27242v1)

## 4. 三个可证伪假设的具体设计

### H1：完成的思考比原nonthinking小适配更能提供新解

**假设**：当前差距的一部分来自调用方式与单请求低吞吐，原27B尚未得到完成推理的机会。它不是“打开thinking必到42分”。

阶段一只测运行可行性。在已冻结012的P2开发题上复用TP4并发路径，读全题面但不读答案；每次1个请求，之后只增加并发至小值以测聚合吞吐。固定模型revision/量化、官方模板、tokenizer与最终网格协议。先用短输出确认API的reasoning/final字段和停止原因，再给完整预算；这不是方法准确率实验。

阶段二用固定P6或P12，开跑前冻结二选一的范围，不因结果删题：

- A：xhigh，每query一次，最大32768总输出token。
- B：low，每query两次，每次最大16384总输出token，固定两个seed。
- A/B最大输出总量相同，但prompt/prefill/实际token及实际秒数不同，所以报告“等最大输出预算的完整方案”，不冒称严格等FLOPs。另给整会话相同墙钟保护。
- 候选只从已完成final段提取；未闭合think、只有思考或长程序残片都计未完成。不再从思考中寻找最后一个矩形冒充答案。
- 若已有完全同身份nonthinking候选，可作历史诊断参照；严谨的A/B是同一新引擎里的xhigh与low，不把量化与引擎更换的效应全归因于thinking。

首轮P2最多131072个输出token，两臂合计；纯输出按实测聚合吞吐 `R` 估算为 `131072/R` 秒。若R=50，这是约43.7分钟；若R=100，约21.8分钟，均不含初始化、prefill和落盘。这里50/100只是条件算术，绝非已测性能。若仍只有4.54 token/s，光输出约8小时，**停止在该路径扩大预算**。根据真实初始化和完成时间再准入P6；不能在未知吞吐时先承诺一次跑完14个query。

**继续条件**：先有完整候选和可接受成本，再用P6/P12检查真query新增。只有某个预算不截断，不足以证明解题能力。若xhigh多数触顶，结论为该预算未充分观察；若全完成仍无新解，冻结这版配置并转H2，不无界加倍。

**TTT取舍**：本周不并行做27B TTT。只有H1已产生可信候选、且无TTT追加一次思考的单位时间收益下降时，再安排小对照“相同实际秒数的额外推理”与“TTT+推理”。原A4的0/2不作永久否决，亦不作扩大步数的理由。

### H2：完整程序与基线互补，且最终选2能保存净收益

**假设**：原27B的程序解能覆盖现有直接网格/4B基线的不同错误。先在固定开发集上产生P0完整程序；如只有残片，暂不比较repair。

- 先使用一个函数接口、已冻结库清单、清晰结束符，输出完整`transform(grid)`。保留思考能力，将“最终代码短”与“思考只能很短”区分。CPU执行只输入demos与query输入。
- 有P0后，仅对同一P0分叉一次反馈修复与一次独立restart；按相同最多调用数、最大输出预算和墙钟比较，保存所有完成/未完成项。反馈只含demo真实差异。
- 直接网格基线候选原样保留；程序无全demo通过或无合法query输出时回退原两个答案。程序通过时，固定规则先保基线第一答案，再把通过demo验证的程序输出放第二槽；若重复则保原第二槽。此规则只是最小可执行起点，不能宣称最优。
- 可以先离线比较 `baseline top2`、`baseline top1 + program top1`、`program top2`。最终选其中一个规则在确认集前冻结，不能逐query按真值挑最优策略。
- **单独记录丢失**：基线原第二槽独有的正确解被替换掉，也要从新增中扣除；两模型置信度不是同一量纲，不直接相加NLL、beam、demo命中和任意bonus。

本项目主指标按当前比赛官方Evaluation使用 **query EM@2**：对每个test output/query取两次尝试中最高的完整网格EM，再对全部query等权平均，即 `mean_query(max(EM_attempt1, EM_attempt2))`。同时报告原始task/query数；新增与丢失也按query等权计数。`mean_task(mean_query(hit in selected two))`仅作补充task宏平均或与作者论文对齐，明确另列，不代替竞赛主分数。统计不确定性可按task聚类，以反映同题多个query的相关性。[本比赛Evaluation](https://www.kaggle.com/competitions/arc-prize-2026-arc-agi-2/overview/evaluation)

`oracle_any`只能作诊断：若oracle无新增，排序救不了；若oracle有新增而真实选2不变，问题在筛选；如果合法候选数少，问题在生成完成率。

在新方案和4B混合部署时还要比较**总12h资源代价**：不能把两套各跑12h的输出合并后声称可提交混合提升。可先离线测互补上界，部署再明确谁占哪些GPU/时段、共享CPU资源和加载代价。没有成本实测前，不武断预分各6h。

### H3：独立实例上的可验证短程序，比继续网格答案小池SFT更值得试

**假设**：专项SFT的监督应教“从例子归纳可执行规则”，不是只模仿高可预测格子；程序给出多个query时还可复用同一规则。此假设尚无本项目收益证据。

先CPU构建候选约200条、最多50个现成training-only family，不调用付费教师、不混入公共evaluation衍生规则。每条保留：原source/task/family、生成器commit、独立base seed、task-level参数、episode哈希、模板版本、目标函数及验证记录。数量上限是研究准备规模，非开训承诺。

数据优先级：

1. **独立base优先**：同一规则的新布局、数量、尺度与颜色关系；每个base至多少量几何增强。旋转四次仍是一个base。`family_id=task_id`只说明来源；新规则需另有组合规则或程序谱系证据。
2. **episode可辨识优先**：所有demos共享应共享的latent参数；query涉及的任意颜色映射/计数分支需由demo约束。只做到每对input/output正确，还不够支持从整个episode推断规则。
3. **短程序目标优先于全长思考蒸馏**：从已知生成器变换函数裁出纯`transform`，只含必要辅助函数；已知task变量可内联，但不能把实例seed、query答案、不可从demos恢复的隐藏参数或答案查找表写进去。执行验证新采样输入，检查函数对多个独立base是否成立。
4. **推理压缩放后**：先有正确且能完成的teacher轨迹，再考虑简短规则摘要+程序目标。没有正确teacher时，生成更多“看起来合理”的短思考只会把错误压进权重。不要把Hourglass的多轮信息约束说成已可低成本蒸馏。

只在H1/H2形成可解释的瓶颈时开一个训练小对照。建议固定相同family/base与输入、同一初始化和有限更新，比较“答案网格目标”与“短程序目标”；训练target token不同，应报告其实际耗时/监督token，称完整目标配置对照，不假装单一长度控制。若要同时研究独立base效应，就再单独设计同family旧base增强vs新base，**不与目标类型一轮交叉铺开四臂**。

评价包含同family未见base的机制检查与P12任务结果，两者分开。前者进步仅证明实例泛化；程序全demo通过也不代替query命中。25步loss下降无新解时不直接扩大到30K。已有010的F0-25纯训练约37.6分钟，且有较长加载，故本轮不能无依据保证两臂加评测只耗1–2配额小时。
