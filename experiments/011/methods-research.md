## 判断与优先顺序

固定 Qwen3.8-27B、4×L4、每周 30 配额小时、提交 12 小时。**下一笔 GPU 预算不宜继续把同一小池从 50 步机械加到 100 步。应先收完 F0-25，再用少量多视角与 TTT 做一个配对实验，判断当前模型是否缺少题内适配；同时给程序生成＋执行反馈一个很小、明确限额的探针。数据规则多样性是下一次 SFT 最有价值的变量，但其质量审查应先在 CPU 完成。**

建议顺序：

1. 完成已经付出训练成本的 F0-25 评价，保留原来比较口径，并审查解码触顶项。
2. 一个固定 checkpoint 上比较“原视角＋转置”与“原视角＋随机采样”；无需先开发大规模搜索或 PoE。
3. 立即允许小规模 TTT，与同墙钟的无 TTT 候选策略配对。不能再以“先有高分 checkpoint”为前置条件；但也不默认全题 TTT。
4. 同轮留小预算给底座的程序生成＋一次执行反馈。把它视为可能提供新解题类型的独立候选来源，不把 Gemini 的效果外推给 Qwen。
5. 只有前述结果或 CPU 数据检查指出清晰问题，才把剩余预算用于一组数据多样性 SFT 对照。若所有方法仍没有目标题信号，留下负面结论，不为用尽配额而继续训练。

此处的 2→3 是执行顺序，数据质量与实例/规则覆盖的 CPU 研究可同时进行；程序分支若实现成本很低，也可与 TTT 探针互换。TTT、程序反馈的相对优先级目前属于研究判断，尚无本项目等预算实证。

## 一手外部证据，以及它们没有证明什么

### A. NVARC：数据多样性和逐题适配有效，但没有证明小池多训几步就足够

作者报告的核心是约 103K 合成 puzzle，经增强形成约 3.2M episode；4B 全参 SFT 使用 32×H100、27 小时。提交做逐题 BF16 LoRA 和候选搜索/重评分。2025 官方私榜为 24.03%；赛后最佳 4B 公榜 29.72%、4×L4、12 小时。其数据构造把摘要组合、输入生成程序和多个输出程序一致性筛选分开。数据配方同时改变了内容与训练量，不是“独立规则数”这一单变量的严格消融。

对我们：优先借其**验证新实例/新组合的办法**，不复制百万增强量；不能用训练 loss 或 25→50 步证明规则迁移。候选统一增强重评分值得保留，但在还没有 oracle 命中时投入昂贵排序没有依据。作者 TRM＋4B 的一项对照没有提升，进一步说明候选数量、互补性和最终选出真解是三回事。

来源（2026-10-10 重读）：[作者论文](https://github.com/1ytic/NVARC/blob/main/nvarc_2025.pdf)，§2、§3、§4.4；[作者代码与公开资产](https://github.com/1ytic/NVARC)；[官方2025结果](https://arcprize.org/blog/arc-prize-2025-results-analysis)。论文 PDF 直接从作者仓库取得并在内存提取文字，未保存副本。

### B. MindsAI/Tufa：TTT 与 AIRV 值得配对测试；消融主要是 ARC1.5

2025 方案为 CodeT5 660M 双 checkpoint、长期 TPU 训练，约 45K 题内增强训练样本和 10K 增强推理样本，逆变换后按完整网格投票。报告的 TTT/AIRV、BPE dropout、自集成消融主要在较小 77M 模型和 ARC1.5 上；匹配样本预算的自集成优于单次更多样本，提示“重启/视角”可能比单次延长更划算，但不能当作 ARC2 或 27B 的效应量。

该报告使用整个待解集合的已知示例做全参适配，不等于 NVARC 的逐题 LoRA；底座预训练极重。公开 SCR checkpoint 使用过 ARC2 evaluation，且模型卡明确 SCR 的额外修复在推理时未带来更好表现。故不把“加修复目标”“上 BPE dropout”列为本周主变量。对我们最直接的是 LOO 构造、几何/颜色一致增强、逆变换整网格投票和等预算适配对照。

来源（2026-10-10 重读）：[2025作者报告](https://github.com/jcole75/arc_2025_mindsai/blob/main/MindsAI_Tufa_Labs_2025_Solution.pdf)，第3–8、10–12页；[原始模型配置](https://github.com/jcole75/arc_2025_mindsai/blob/main/src/modules/config/model_configs/codet5_660m.py)；[660M权重](https://huggingface.co/mindware/arc-codet5-660m)；[SCR说明](https://huggingface.co/mindware/arc-codet5-660m-scr)。作者报告写15.42%，官方最终私榜表列12.64%；保留口径差异，不用两者相互替换，也不归因给 Tufa 2026 公榜方法。

补充的逐项消融来自 ARChitects 的 ARC1 400题：8B 已专项训练 baseline 18.3 → TTT 44.5 → 16视角 62.5 → PoE 67.6 → DFS 71.6。它是累计增加组件的对照，计算量也增加，不能视为等预算收益。更深 DFS 将 oracle 从76.0提高到83.5，但选2仅71.6→71.8、总时间20h50→134h43，说明盲加搜索量会被排序和成本限制。[作者论文表2/3](https://arxiv.org/html/2505.07859v1)，2026-10-10重读。全部为 ARC1，不作为本项目 ARC2 预测。

### C. Poetiq：执行反馈有明确实现，但对本地 Qwen 的净收益未证实

官方核验的是 Gemini 3 方案在 ARC2 Semi-Private 的54%、约$30.57/题，非 Kaggle 无网12h运行。源码依赖API模型，公开的是求解器而非高分底座权重。实际循环把生成代码在已知示例上执行，把错误、形状差异和格子差异反馈给模型；全示例通过就结束该专家，否则最多10轮，多个专家按预测输出聚类。

这是可审阅的反馈机制，不是 Qwen3.8-27B 的受控消融。我们应先问“一次反馈是否优于同成本重新生成”，不能只展示第一次错、第二次对的个例。示例全通过也不能保证 query 正确；真 query 标签不参与执行反馈和选解。

来源（2026-10-10重读）：[官方核验说明](https://poetiq.ai/posts/arcagi_verified/)、[配置](https://github.com/poetiq-ai/poetiq-arc-agi-solver/blob/main/arc_agi/config.py)、[生成—执行—反馈循环](https://github.com/poetiq-ai/poetiq-arc-agi-solver/blob/main/arc_agi/solve_coding.py)、[多专家投票](https://github.com/poetiq-ai/poetiq-arc-agi-solver/blob/main/arc_agi/solve_parallel_coding.py)。

## 最小、可证伪的手动研究

以下全是待运行设计；步数、候选数和上限不是已经证实的最优值。每组保留完整候选、时间和失败原因，由用户手动发起，无自动测试套件。

### V：第二个视角能否比第二次随机采样更常带来新解

**假设 V：** 单视角的错误中存在可被表示变换修复的部分；转置能提高真 query 的候选覆盖。

- 固定同一个 checkpoint、formatter、thinking设置和题目；先用已有 P6（6 task / 6 query）做先导，完整报告 H/E 和 S/M/L，不临时剔除长题。现有代码已有转置入口，先复核整题变换和逆变换。
- 三个候选来源：原视角 greedy O、原视角固定 seed sample S、转置 greedy T。比较 O+S 与 O+T 的 exact-match@2、新增/丢失；每臂恰好两个机会，不用 query 标签选择 S 或 T。
- 如同一 checkpoint/config 的 O 已完整保存，可复用其输出作配对，明确是历史复用；不把不同 checkpoint 的答案拼成“同模型对照”。记录实际 decode/prefill合并时间，不能把相同候选数当相同计算量。
- 先不加8/16视角，不开发PoE。若 O+T 出现新命中，下一步才在 P12 全体比较等总时间预算；若 O+S 同样更强，也接受该结果。
- **停止条件：** P6无新增且 T 多数重复旧错误，便不扩大到16视角。若仅有一个新命中，只允许一次 P12 扩展/独立小确认，不能宣布普遍收益。如果各候选全部为0，排序方法没有挽救空间，应转适配或程序表达。

这是成本最小的覆盖诊断，不是“0/6足以永久否定TTA”。若转置含有格式错误或未逆变换，先判运行无效，不作方法结论。

### A：少量 TTT 是否比同样时间多看几个视角更划算

**假设 A：** 冻结底座已具备部分规则能力，但需要用当前题的 demonstrations 将它调动；4个更新可能增加完整 query 命中。

- 对同一 P6 运行 A0与A4；先固定4个optimizer updates、accum1、microbatch1，保留标准 r8/alpha32、现有模块列表和同一个起始 checkpoint。不在这一轮同时增加 GDN targets、换loss或改数据格式。若只能用已有8步入口，可用A8替代，但须在开跑前写定，不能看到结果后追步数。
- 每题重置 adapter、optimizer；只用该题已知示例的 LOO 训练，整episode一致增强，答案mask，不能读取真query答案。2-demo任务留一后1个context仍合法；不机械套用离线D2的“至少2个剩余demo”门槛。
- A0和A4使用完全相同 O+T生成；这给出固定候选下的适配差异。另记录 A4 的真实总时间，用不更新权重、相同时间内可完成的预先排序视角/采样作为资源对照；不凭理论step速度断言公平。
- 同时记录题内训练目标是否能拟合、留出已知示例是否改善，但这些只解释机制。若做示例留出诊断，留出的那个输出不得出现在适配、程序反馈或候选选择里；需与“全部demos可用”的正式 query实验分开计分，不能把训练样本重建称为泛化。
- **停止条件：** 达到预先固定的 P6/时间上限就停；只降loss、训练示例全对但真query仍0，没有扩大每题步数的依据。若有1个真实新命中，下一次先重复该类效果/扩大固定P12；不直接从4步扩成全题128步。若0/6但有独立示例留出改善，保留适配线索，先检查规则覆盖，不作永久否定。

TTT入口目前未实现；研究交接应说明这点。允许写一个能保存输出的小型手动入口，不为它重写训练平台。A0/A4实验只回答当前 checkpoint 与目标，不能否定所有未来专用化权重上的 TTT。

### P：程序生成与真实反馈能否提供网格分支没有的候选

**假设 P1：** 同一27B的程序表达可解决部分直接网格生成失败题。**假设 P2：** 第二次调用接收执行差异，比同预算独立重新生成更有用。

- 使用同一个 Qwen3.8-27B 底座，先关闭网格SFT adapter；这保留已选模型的原程序能力，不引入新底座。它与网格checkpoint的比较属于完整方案效用比较；反馈净收益只在同一底座的代码臂内比较。
- 从 P6按清单顺序跑，不能按隐藏答案或人工“可写代码”的判断挑题。单题总墙钟硬上限建议8–10分钟，先总计不超过1小时；完整保留超时/没来得及生成的题，不报仅完成题准确率。
- 每题先生成 P0 一个无外部依赖的 `transform(grid)`。执行仅限题内demos；反馈应给真实异常、形状和差异，不由外部教师暗示规则。
- 对相同 P0 分叉：P-repair=一次有执行反馈的修复；P-restart=一次不看反馈的独立生成。两臂使用相同每次token/墙钟上限；这是三次模型调用，但 P0共用。固定seed，先一轮，不上8专家×10轮。
- 每个方案最多保留2个不同query输出。筛选只看demo表现、预先规定的简洁规则和输出合法性；示例全匹配不足以证明正确，严禁按query真值替换候选。CPU执行设置时间/内存上限，禁网、不读取解答文件；这是求解器的执行约束，不是新增工程测试体系。
- **停止条件：** 6题都没有可执行程序，则停程序搜索扩容，先判提示/表示或程序能力不足；程序可执行但始终不拟合demo，停止增加repair轮数；拟合demo却query仍0，记录过拟合，不强行替换网格候选。只有真实query新增且单位时间有竞争力，才进入 P12/确认集合。

若一次repair和一次restart都未完成，不能称“反馈失败”；记录预算不可行。每次最多几百至约千token只是开工参数，真正可行值须按实测吞吐；未经测量不能承诺8分钟足够三次调用。

### D：下一次 SFT 比较独立实例/规则覆盖，不比较日志行数

**假设 D：** 在相同样本暴露/长度范围内，更多独立实例或规则族覆盖，比反复旋转换色同一base更可能改善留出任务。

先在CPU完成约20个生成episode的人工审查：生成器是否共享潜在配置、示例是否覆盖query关键变化、目标pair是否进入demo、输入是否可能多解、增强是否可逆。JSON合法和固定示例 `validate()` 通过都不能代替规则一致性。优先复用已经生成的新base，不先下载ARC Mega全量或调用付费教师。

将两个问题分开：

- **D-instance（先做）：** 固定相同family集合、来源比例和约400个episode：旧base的多次增强 vs 同family的新独立base、少量增强。匹配长度桶、target-token量、初始化、格式和LR计划；报告真实GPU时间。它只测实例变化，不宣称新增规则。
- **D-family（后做）：** 同样规模下更多不同task/生成器family，减少每family重复。`task_id`只能证明来源分组，不是语义规则距离；需要规则描述/程序谱系审计后，才称“规则多样性”。不同时引入新的表示、TTT、GDN和长序列上限。

**停止条件：** 不能构造来源与规则一致的episode，则先停止GPU训练；两训练臂25步后若只有train loss变化、无独立实例留出改善，也没有P12新候选，则不直接扩成大池长训。若仅同family新实例改善，记为实例泛化，不能声称ARC2新规则泛化；若P12仍0但固定桥接集有改善，仅允许一次窄范围追加确认。不要因50步仍0判定NVARC的数据路线无效，因为训练量和分布相差极大。

NVARC合成数据的evaluation规则衍生部分、Tufa SCR/ARC Mega的evaluation来源要单独追踪；不能整包混入后仍把公开eval/C12称为未见。先用来源清楚的training-only生成器、官方训练划分与自有独立base。

## 处理0/14地板效应：保留目标，增加诊断层，不能换一套容易题报喜

1. **主终点仍为真query完整网格EM@2。** P12来源分开、全query保留；候选oracle只用于运行后分析。凡某题在预算内没有结果，计入完成率与整个方案预算，不能从分母消失。
2. **先区分覆盖与选择。** 若4个候选oracle也是0，PoE没有解可选；若oracle>0但选2为0，才优先排序。单视角0并不等于多候选oracle=0。
3. **用demo留一作机制探针。** 预先选定的demo输出可由独立评分代码评估；不给适配/反馈链看到该输出。它来自已知题、示例较少，既不是私榜也不是独立新任务，不与P12 query分数合并。
4. **必要时加固定桥接B8。** 只在P12继续全0、方法无法排序时，从尚未用于本轮决策的旧ARC1任务留出中按输入长度/示例数分层、固定seed选8个task；不按当前模型成绩挑“接近会做”的题，不动C12。所有方法看同一B8，单独报告旧分布结果。只允许一次建集，不能反复换题直到有收益。短输入只保证低成本，不保证难度较低。
5. **错误性质只作解释。** 记录尺寸错、内容错、合法但恒等复制、超长重复、示例拟合率、执行错误、生成重复率及耗时。逐格正确率、teacher-forced loss和合法率不能代替解题分数，也不能用于对隐藏query偷偷改格。
6. **C12仅确认冻结方案一次。** 先在P12/P6做选择；有可信覆盖线索后再比较冻结完整方案与固定基准。C12揭示反馈后标记已使用，不继续叫盲测。任务内多query相关，14个query不是14个独立任务；避免用小片精确百分比作比赛预测。

## 30配额小时应如何控制研究规模

官方L4扣额是两倍；历史部分账差约2.2倍、另有未解释异常，不能当稳定实测倍率，四张卡也不是四个worker。慢加载出现过约6600秒，011另核到S4约3309秒。以下保留为研究阶段的候选分配，**不作为执行预算**；最终以011计划的实时剩余额度、23小时承诺和储备为准。训练、生成、安装、加载均计费。

| 工作 | 建议配额小时上限 | 用途与超限处理 |
| --- | ---: | --- |
| F0-25闭环与必要的触顶补查 | 3 | 先完成已有投资；加载异常侵占预算时不顺延后续全部计划 |
| V：P6第二候选，必要时扩P12 | 3 | 不先做16视角；无覆盖不开发排序 |
| A：P6有限TTT与时间对照 | 5 | 包括入口的真机核对；失败不再加步数 |
| P：有限程序/反馈探针 | 3 | 上限以内先完成几个完整分叉；不是让每题无限思考 |
| D或一次机制桥接，二选一 | 6 | 根据前四步决定；数据审查不通过则不训练 |
| 冻结方案确认与总时长抽样 | 4 | 若没有候选方案可以暂不使用C12 |
| 冷加载、保存和异常余量 | 6 | 不预花，不借口“还有余额”追加弱分支 |
| 合计 | 30 | 约13.6小时正常墙钟的条件算术，不是保证值 |

实现上尽量一个底座驻留、顺序切adapter/禁用adapter、缓存失效正确处理；不要为每个小分支重新读取55GB权重。若新入口的准备工作明显超出小实验规模，交给用户按最终计划实现，不自行开展大规模训练或扩建工程。

提交12h是另一个限制：先读取隐藏task和query数量，按题共享TTT/程序、按query计算生成；用代表性长短题的实测耗时和尾部预算，覆盖全题后才扩大搜索。小探针的每题8分钟不会自动成为可部署方案：240题串行即32小时。部署时必须用有证据的适配准入或更快布局，而且不能凭题内demo拟合独自保证选择正确。

## 最可能改变路线的结果

- **V有真query新增、A无新增：** 下一轮先投入视角覆盖与选2，TTT暂缓扩量。
- **A显著优于A0且等时间对照：** 保持短程TTT，扩大独立题确认；专项SFT继续训练“易于题内适配”的初始化，而非只追零样本loss。
- **P能产生网格分支没有的真解：** 给本地程序分支一份提交预算，之后研究候选互补；无需改底座，也不要求一开始做大型agent框架。
- **只有D的实例留出改善：** 继续数据质量/覆盖研究，暂不宣称未见规则收益。
- **全部仍0且格式已正常：** 本周结论应是当前数据量/表示/推理方式尚无目标题信号；停止机械延长同池、保留权重和失败案例，为下一轮设计更强的规则与监督来源。既不许诺金牌，也不宣布模型上限。
