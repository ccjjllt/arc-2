## 3. E0：修正评价，不把整周都花在重新评旧题上

### 3.1 三种集合分开

- **H25历史桥接**：007已评24 task、25 query。底座补齐同题greedy，输出上限统一2048；G1只补原960上限的5query。其余20条greedy在权重、formatter、环境相同且无截断时复用，不重复烧额度；若环境/内核改变，先少量配对核对再复用。原0/5和6/20记录永久保留，新统一口径另建结果。
- **H-new项目留出**：从原100题holdout里26个非ARC1任务选12个，覆盖prompt大小；不得加入训练或其生成器。按输入侧元数据分层、固定seed与清单，不能挑已知容易题。另14个留作后续确认。已看过`342dd610`必须显式标记，不能冒称全新盲测。
- **E24公共evaluation开发片**：从官方120题按prompt长度分层选择24个task，全部query；只用公开题面决定入选，保存清单后才查看答案评分。其余96题保留给冻结方案确认。E24反复用于选择后就叫开发集，不能再称最终盲评。原始底座预训练覆盖未知。

E24和H-new各有用途：前者接近比赛评估任务分布，后者便于在不使用公共eval答案训练的前提下研究训练覆盖。两者不合并成总分，也不与历史30.14相比较。若首会话预算不足，先H25与固定H-new，再完成预先列好的E24；报告完成/未完成清单，不按运行截止前的容易题估算全体成绩。

### 3.2 配对方法

同一次模型加载，比较 `base` 与 `G1`：无adapter/禁用adapter，以及加载或启用原adapter；不要为每一题重新加载27B。必须确认禁用的是LoRA而不是卸掉了必须保留的权重。每次切换权重清空混合cache。保持BF16、原模板、thinking=False、greedy、最大输出2048、同样完整prompt。先不加随机sample。

逐query保存四类：两者都对、仅底座对、仅G1对、都错。报告合法率、尺寸正确率、截断、exact-match、时间、输出tokens；附按来源/输入长度的分组。exact-match仍按query平均，与竞赛口径一致；不确定性分析或重采样以task为簇，不能把同题两个query当独立证据。

这一步决定G2的初始化：G1在新集合有正向证据就继承G1；若明显回退，保留G1作历史参照，G2从同一原底座重新初始化LoRA。一两道题的差异只支持继续小实验，不足以宣布优胜或估算私榜。

## 4. D2：把现有G2池改成更有信息量的训练样本

本地CPU先做，保留007原池不覆盖，产物另存 `experiments/008/data/`。不要为达到30K而优先填增强副本。

1. 继承892/100/8划分和上游generator排除清单；增加 `origin`（旧ARC1 train/eval/非ARC1）、`base_instance_id`、query类型与真实token数。`family_id=task_id`不宣称完整语义去重。
2. 官方端先覆盖所有test query以及demonstration留一，不要先把test[0]展开24遍。移除仅因目标等于另一个demo输出而删除样本的笼统判断；保留目标pair与demo隔离，记录可能退化/重复。
3. 生成端优先提高独立base数，例如从750扩至约3000，每个base先取1–2个一致增强，而不是24个。3000是首轮CPU数据目标，不是新增规则数量或GPU必须全部训完的承诺。后续不足时再按实际消费需求生成。
4. 抽样顺序固定为来源→task→base→query→增强，防止有2个base的规则获得双倍任务权重，也防止短样本行数多的任务主导训练。来源40%官方/60%生成作为起点；另报告真实新任务占比，不把V2当作新任务标签。
5. 在不改变数据来源的前提下，保证206个非ARC1训练任务有抽样机会，特别是无当前V2生成器的55个任务。若要提高非ARC1权重，另记录为配方变化，不把它与GDN/rank变化混在一起。
6. 人工抽查至少20个base，兼顾长题、非ARC1、多颜色、重复输出；检查示例是否足以说明query要用的规则。读清生成器共享变量和校验函数的语义，不将合法矩形等同于可学习episode。需要规则oracle时使用实际可执行的变换，不靠模型自称正确。
7. 用固定tokenizer做完整 `prompt+target+EOS` 统计，形成≤1024、1025–2048、2049–4096、4097–8192、>8192桶；每桶报告task覆盖、独立base、监督token与来源。丢失的任务列出，不能静默截断或用`overflow_len`假装训练了长桶。

第一条训练分支D2的目标是联合修正“实例少、query偏置、长度覆盖不足”，不是证明其中每一项的独立因果效果。若联合修正有效，再用相同初始化的小消融分开实例与长度；不要一开始铺满全因子矩阵。

## 5. G2a：先做数据与长度实验

默认保留G1的r8/alpha32、q/k/v/o与MLP目标、BF16、答案mask、thinking=False、microbatch1/累积4。底座仍为单进程四卡按层放置，不能称为TP/FSDP/DDP。

新增 `--init-adapter`（建议接口）表示只继承权重，**数据池、cursor、optimizer、scheduler重新开始**；`--resume`仅用于同一阶段中断后的精确恢复。阶段间记录旧、新训练量，不能把新阶段步数伪装成旧曲线连续的损失。

训练起点：lr 2e-5，10步warmup，小阶段预计100–200次更新、即400–800条实际episode，保存每50步的独立adapter，最多保留少量候选。到墙钟/配额上限立即保存退出，以真实完成量报告，不承诺4K样本也能按G1速度跑满200步。

长度安排先做几条真实2K/4K的手动前后向测量，然后按桶混合，初始建议≤1024占20%、1025–2048占40%、2049–4096占40%。这是可修改的实验配方，先统计池能否支持，不通过重复少数家族凑比例。>4096桶明确未覆盖；4K可行后选少量8K测成本再决定是否需要G3/内核优化。不能删掉关键演示后仍声称完整episode。

新阶段保存：adapter、配置、实际sample/base/task清单、输入/目标token累计、分桶消费、每卡显存、训练与Notebook时间。评价先greedy，用E0同清单；学习率与checkpoint由新增/丢失解题及成本选择，不能按最后loss最小自动决定。

决策：若新任务/公共eval无净收益或旧能力大量损失，停止扩至1000–3000步，先分析损失类型；若获得可重复的正向信号，再投下一周扩大有效数据。若主要受长序列OOM/极慢限制，转性能分支，不能回到只挑短题训练。

## 6. A1：用小实验决定在线适配和第二次尝试

该阶段可先在G1做小读数，也可与G2a独立加载评价合并；不必等某个任意分数阈值。大规模逐题TTT仍需成本收益证据。

### 6.1 同视角sample → 变换视角

固定12个task的小开发片，从已声明的H-new/E24中按长度分层选，不能按已知对错挑选；结果同时报告新增解题与原有正确答案的丢失。比较：

| 配置 | 用来回答的问题 |
| --- | --- |
| 原greedy + 同视角sample | 当前参照；仅此小片需要补采样 |
| 原greedy + 转置后的greedy，再逆变换 | 两次生成换成不同视角是否更有效 |
| 上述基础再加旋转/固定换色，最多4个候选 | 更多视角是否产生新真解，是否需要排序 |

同一视角的所有demo、query统一变换，逆变换后按网格去重。用task_id/query/view的稳定hash派生seed，不能依赖进程hash或运行顺序。每个候选独立有效cache，不移植未验证的混合cache DFS。

先报告候选oracle和实际选2；若oracle不增，暂不做昂贵PoE。候选超过2时，先比较固定“原greedy保留一席＋变换票数/固定次序另一席”；有覆盖价值后才增加少量跨视角候选NLL重评分。评分只能用题面、候选和已知demos，不看query真值；重新归一化/长度归一化规则必须固定，不能套用16token模型的DFS阈值。

### 6.2 0/8步TTT

在同样小片、同一离线checkpoint上比较0步与8步，使用相同候选/视角。每题从相同adapter初值重置，只训练当前题的demonstrations/LOO及一致增强；隐藏query输出绝不参与训练。多query共享该题的适配，不能重复算成多份模型加载成本。

同时比较等墙钟下“不TTT但多一个视角”的最终选2。记录TTT净新增、丢失、逐题训练/生成/重评分时间。没有正向信号就暂停扩展；有信号再用更大的固定清单确认。16步仅在8步已显示值得继续研究时增加。不要只按训练loss路由TTT，低loss不保证query正确。

启动条件是完整episode覆盖或提交吞吐已成为主要约束，并且转换/新格式训练的成本值得花；不是因为当前40个候选合法率低。保留完整词表checkpoint，比较相同task清单、有效训练量以及相同墙钟下的精度与速度。

G3不能输出Python或自然语言CoT，不能作为唯一资产替换所有完整词表分支。若同预算表现下降且吞吐收益不足以弥补，就结束该分支。

### 7.3 同一27B的程序互补

当网格分支在新题上停滞，允许对同一12题开发片做2个Python程序候选、至多1次基于实际示例差异的修复。优先用原完整词表底座，避免要求网格SFT adapter天然保留编程能力；无需另选模型，也不启用SOAR。

给模型输入demonstrations与query input；执行已知示例，反馈尺寸差异、错色位置和简洁对象统计。执行进程无网络、无任意文件访问并设时间/资源上限。算法内用示例验证合法，属于求解过程，不是工程测试套件。

程序全部拟合示例仍可能是假规则。记录程序oracle与最终选2，先固定保留一个网格候选、第二席才考虑有证据的程序候选；不能依靠query真值挑程序。ABPR的Prolog结果只支持反馈思想，此Python配方是待验证假设。不先写大型DSL/遗传框架或调用付费教师生成海量轨迹。

若这个小实验没有新增解题，暂停；若确有互补，再考虑用生成器的可验证程序构建专项程序/修复数据。此时必须按family隔离，输入程序仅接受query输入，不能把生成器已知输出硬编码成解题程序。

## 9. 12小时部署与金牌/奖金的研究标准

正式时间按整Notebook算：安装/加载/保存＋每task适配＋每query候选生成＋重评分。四卡按层放置是一个模型worker，不把单题预算乘4。提交程序读取完整test清单，先覆盖每个query并及时落盘，再把剩余预算分给有开发集证据的适配/候选；一个慢题不能耗尽全部任务预算。

用未参与调参的任务估计平均、长尾与按实际文件长度分布加权的时间，再做完整离线演练。输出尺寸预算不能读取未知答案。只有真实Kaggle评分结果才写公榜/私榜成绩。

当前公榜第8条目36.94、金牌名额附近33.89仅作2026-10-01快照。研究目标是相对可运行参照获得可重复的新增解题并控制丢失、保证12小时完成，而不是瞄准某个固定百分比。历史复制方案可以保留为参照资产；只有同题比较支持互补时才占用最终两次尝试之一。

金牌由最终排名决定，排名奖金仅前8；另有基于方法质量的研究奖。创新证据应来自可复现的数据/适配/互补效果和消融，不来自模型大小或新框架名称。不能保证金牌或奖金，但可以把有限算力集中到可证伪、能改变决策的研究上。
