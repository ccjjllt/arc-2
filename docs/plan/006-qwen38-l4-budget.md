# 006 — Qwen3.8-27B：L4×4训练与12小时答题方案

日期：2026-09-29。对应进展：`docs/progress/006-qwen38-l4-budget.md`。

状态：研究与实现交接；选定模型，未启动训练或模型推理。代码与手动实验由用户执行。

## 目标与继承结论

固定 `Qwen/Qwen3.8-27B`，不继续展开其他模型选型，不使用SOAR。参考NVARC的“赛前ARC专用训练→当前题示例适配→增强候选→选两解”，以L4×4和12小时为实际约束。

研究假设：更强初始化配合ARC2专用数据，可能以较少候选/较少TTT步数获得有竞争力的解题能力；需要手动实验，不能由参数量推断效果或速度。

## 两个阶段分开预算

### 阶段A：赛前专项微调

使用官方训练题、ARC-GEN V2和来源清楚的合成episodes适配模型；继承004中的配色一致性、family划分与旧数据保留方法。跨多次开发会话保存和恢复adapter，不把全套专项训练重复放进每次submission。

12小时评分限额不是赛前训练总额度。赛前训练仍受每次Notebook会话时长、账户GPU配额及L4离线要求限制；本轮没有核实账户剩余额度。

先使用冻结底座的LoRA。保留原tokenizer/chat template及完整网格，不从零预训练，不首先进行27B全参数Adam训练。

### 阶段B：提交时答题

加载阶段A的固定产物，完成全部隐藏任务；可选的小步数TTT、模型切换、预热、生成、候选排序及JSON写入都计入12小时。

先建立 **SFT权重＋有限候选** 的完整路径，再加入TTT比较增益。TTT是NVARC中值得迁移的研究方法，不要求第一版对所有题进行大量梯度更新。

## 训练实现起点

| 项目 | 建议 |
| --- | --- |
| 精度/并行 | BF16冻结底座＋LoRA＋受支持的FSDP2分片，4×L4 |
| 范围 | text-only任务，冻结视觉模块；按实际模块结构适配语言层 |
| Adapter | 先参考官方rank8/alpha32配方，必要时研究rank16/32；不照搬NVARC rank256 |
| 长度/batch | 每卡batch1，先用可完整放入2048/4096的episode；较大网格单独扩长度，不能截断答案 |
| 激活 | activation checkpointing；记录激活、logits和临时all-gather峰值，不仅计算常驻权重 |
| Loss | 优先核对现成chunked/fused线性交叉熵支持，避免一次物化整个[seq,vocab]；不假定换loss无需适配 |
| 产物 | adapter、tokenizer/formatter配置、数据revision、实际环境与训练记录 |

依据：[NVIDIA Qwen3.8配方](https://docs.nvidia.com/nemo/automodel/recipes-e2e-examples/qwen3-8-27b)、[同架构Axolotl训练配方](https://docs.axolotl.ai/docs/models/qwen3.5.html)。前者已公布的运行使用8×H100，并非4×L4；迁移显存和吞吐未实测。

若BF16方案显存或通信成本过高，研究有现成实现的QLoRA＋分片；量化损失作为单独变量。4bit裸权重约13.5GB不代表完整训练能装入单L4。

## NVARC方法迁移

| 保留的思想 | 对27B的调整 |
| --- | --- |
| ARC任务式SFT | 使用示例→新输入→输出的episode；保留语言模型原词表，先不改为16-token模型 |
| 旋转、转置、换色 | 同一episode一致变换；推理后逆变换再汇总；增强数按实测时间选择 |
| 逐题LoRA | 只使用题目提供的已知示例输出；每题从相同离线checkpoint重置adapter |
| 示例重组/留一适配 | 有多个示例时可轮流作伪query，训练目标仍是已知示例；不读取隐藏query真值 |
| 多候选与增强一致性 | 先少量候选和视角，再依据新增解题/时间扩大 |
| PoE重评分 | 作为独立研究项，重评分prefill和输出成本计时；不直接沿用16-token NLL尺度和阈值 |
| 12小时分配 | 先覆盖所有任务，再把剩余预算用于有价值的适配/搜索；不机械复制4B的每题训练量 |

不能直接搬用旧DFS缓存逻辑。Qwen3.8含Gated DeltaNet与全注意力两种状态；tokenizer、cache和LoRA模块均不同。先用新架构受支持的生成路径。

离线LoRA可在赛前合并一次，随后导出部署权重。在线TTT保持大底座常驻，只更新/切换小adapter，不应每题重载或写出约55GB完整模型。adapter切换后不得复用旧权重下的缓存状态。训练框架和推理引擎之间的adapter支持需核对，先用同一受支持模型路径减少转换成本。

## 推理布局：训练分片与推理并行分别选择

| 布局 | 模型副本 | 作用与限制 |
| --- | --- | --- |
| BF16 TP4 | 1个副本占4卡 | 精度参考与初始可运行路径；卡间通信频繁，不能当四个独立worker |
| 量化TP2×2 | 2个副本，各占2卡 | 可研究吞吐/显存折中；选择受支持的FP8或INT4实现，不能只改dtype就算量化完成 |
| INT4单卡×4 | 4个副本，各占1卡 | 可能适合按题并行推理；上下文、GDN状态、量化内核和精度须实测；不据此声称单卡可TTT |

首轮部署优先研究 **INT4 TP2×2** 的吞吐与精度，用BF16 TP4作参照；单卡四副本等加载余量实测后再比较。已有[Red Hat Qwen3.8-27B INT4配方](https://huggingface.co/RedHatAI/Qwen3.8-27B-INT4)可参考，采用AWQ smoothing＋W4A16 GPTQ，并保留embedding、lm_head等层的高精度。对我们赛前合并后的权重重新量化，并以ARC分布校准；不能直接把原始基座的量化文件称为已包含我们微调结果。

TP2/TP4在官方头数上可整除，但这只是必要条件；还需部署引擎和内核支持。实际应按整套ARC工作负载比较吞吐，不能单凭副本多就认定更快。

推理量化与训练是独立选择：赛前可BF16 LoRA，赛前合并后再导出量化权重。动态TTT如果和量化引擎不兼容，先比较不做TTT的固定权重路径，再决定是否值得增加适配工程。

vLLM已有qwen3_5 LoRA推理支持，但它不负责梯度训练；训练得到的adapter必须与实际推理引擎支持的目标模块一致。SGLang不同模块的支持范围也需按当前版本核对，不能只看到“支持LoRA”就假定全兼容。

上下文首轮按实际输入长度从8K左右研究，长题再加长。按模型配置计算，完整注意力的BF16 KV缓存为每序列每token约64KiB，8K约512MiB；这还不含GDN状态、缓存池、临时张量与CUDA graph。不能直接采用模型262K最大上下文作为比赛默认值。

## 12小时的预算核算

设：`T_eff = 43200秒 - 加载/编译/输出等固定预留`，`N=实际task数`，`W=真正独立处理任务的模型副本数`。

粗略的平均worker预算为 `W × T_eff / N`。这不是每道题必须等时的调度策略；多query任务与大网格需要更多时间。

按官方文案240题、预留1小时，`T_eff=39600秒`，规划示例为：

| 布局 | W | 每题平均worker墙钟预算 |
| --- | --- | --- |
| 四卡共同服务一个模型 | 1 | 165秒 |
| 每两卡一个独立副本 | 2 | 330秒 |
| 每卡一个独立副本 | 4 | 660秒 |

单卡副本可能更慢，以上不能解释成量化后必得四倍吞吐。预算包含该worker为该题做的全部TTT、prefill、decode及排序；实际task数需读取输入文件，不能写死240。

进一步假设240题都只有一个test input：

- 每题生成2个候选，每候选平均4096个输出token，需要约197万输出token；11小时内仅解码就需约50 token/s的**全系统聚合吞吐**。
- 每题8候选、每个4096 token，需要约786万输出token，解码下限约199 token/s。

这些是需求计算，不是L4实测。prefill、TTT、评分、多test inputs和负载不均衡会提高实际要求。reasoning token也计入输出预算，不能让默认长思考无限消耗时间。

初始研究使用紧凑网格答案和明确的thinking/输出预算，按长度分组处理；保留短思考与直接输出的效果比较。不要为省时间静默截掉答案，也不把关闭思考预设为一定更优。

## 用户接手的三组手动研究

1. **R0：训练可行性。** 用一小批完整短/中/长episodes手动跑几十步，记录每卡峰值、step time、tokens/episode、loss实现；据此调整rank、长度和分片。它回答训练能否实际运行，不代表研究方向的分数结论。
2. **R1：无TTT推理基线。** 在同一批诊断题比较BF16与可用量化布局，记录完整答案命中、实际生成token、prefill/decode、总时间。先建立阶段A产物能在预算内答题的起点。
3. **R2：TTT净收益。** 固定阶段A权重与题集，小规模比较0/8/16个TTT optimizer steps及相同时间下的候选数量。按新增/丢失解题和总时间判断；若模型训练不足或适配目标不合适，不把短程无收益当永久否定。

这些步数仅是起始实验点，不是已验证最优值。首轮不要求复刻NVARC的全部augmentation和搜索量。
