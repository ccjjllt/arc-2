# 002 — 基于现有方案的提分研究

日期：2026-09-29。状态：研究设计，尚未启动实验。开始实际实现后建立 `docs/progress/002-strategy-improvement.md`。

## 背景与继承结论

承接 001。用户当前约 30 分，提供的是 NVARC 复现 Notebook。必须以版本 `314617319` 的实际代码为准；若已包含 TTT、增强或集成，应研究它们的边际收益。

优先使用已有公开权重及 Kaggle L4×4。完整重做 NVARC 离线训练的算力远大于逐题微调，不把两者混为一谈。Colab v5e-1 的迁移成本可能高于收益，暂不作为主线。

用户不需要工程门禁或测试文件。本轮所有实验手动启动和分析，只实现回答研究问题所需的代码。

## 目标与研究假设

目标是提高同一资源预算下的完整网格命中率，并找出可迁移到未见题的改进。

- H1：当前主要损失可能来自运行预算、漏跑或候选选择，保持初始 checkpoint 不变也可能获得收益。
- H2：两次答案的互补性和模型之间的互补性，比重复近似候选更有价值。
- H3：只有候选生成能力不足时，定向数据与继续微调才值得优先投入。
- H4：逐题独立的 TTT 可以在四张 L4 上并行；是否优于现有调度需看实际吞吐和尾部耗时。

以上均为待验证假设，不是已有实验结论。

## 数据与指标

先追溯 checkpoint 训练来源。上游 NVARC 的 ARChitects 训练配方含 `arc2_evaluation6`，故不能默认 ARC-AGI-2 public evaluation 是干净留出集。

- 已见公开题：只作机制诊断、耗时和错误分析，并标注可能训练重叠。
- 可确认未参与训练的题或新生成任务族：作为留出实验材料；同一生成模板及其变体尽量同组划分。
- Kaggle 公榜：用于有限次数的整体确认，避免围绕每日反馈调参；不代替本地研究记录。

每组手动实验记录：完整网格命中率、正确候选是否曾生成、最终两答案是否选中、相对基线新增/丢失的解题集合、逐题耗时和显存、超时/漏跑、总耗时。仅在有可用真值的材料上分析“正确候选”；隐藏题不能据此计算离线指标。

## 实验顺序

### A. 固定初始 checkpoint，定位推理损失

1. 原配置运行固定的小规模题集，保存候选、排名和逐阶段耗时。
2. 只改变一项主要因素：已有 TTT 步数/学习率、候选数或 PoE 视角数。
3. 区分没有生成正确答案、生成了但未选中、没有足够时间处理三类问题。
4. 比较每单位时间新增解决的题目，兼顾因预算调整丢失的题目。

TTT 用当前题目提供的示例输入输出进行适配，不能读取待预测输出的真值。TTT 意为推理时适配，不是软件自动化测试。

### B. 候选与预算分配

- 研究增强还原后的候选去重、视角一致性和现有置信度排序。
- 保留第一答案，从现有合法候选中选择不同的第二答案；没有其他候选时不凭空生成。第二答案即使置信度较低，也不会抵消第一答案的命中。
- 研究按任务耗时分配预算，以及四 GPU 独立 worker 的吞吐。先沿用能运行的布局，再比较调度变更。
- 在 12 小时限制内为加载、编译、长尾任务及输出写入留下实测所需余量。

### C. 定向继续微调

- 根据 A 中“正确候选从未出现”的失败题型选取数据；不要只因为有 GPU 就重训。
- 从现有 ARC 权重继续小规模 LoRA/SFT，先短训练，观察留出任务与旧能力变化。
- 针对对象关系、条件组合、尺度变化等已观察到的薄弱类别补充公开或自建合成任务，并记录来源和训练覆盖。
- 精度、序列长度、batch 和 adapter rank 根据显存实测选择；4×24GB 不能按单卡 96GB 安排模型。
- 保存 checkpoint，再导出比赛离线环境可加载的权重与依赖。

### D. 互补解题器

如果 A–C 仍暴露明确缺口，再选择程序搜索、TRM 或其他模型分支。已包含的分支不重复引入。以新增解决的任务衡量价值，并从总预算中分配算力。

程序在已知示例上的一致性检查属于求解算法，可在手动启动的求解过程中执行；不新增软件测试文件。

## 拟修改的代码与产物

取得基线源文件后再定实际模块名，避免空建架构。预计只涉及：

- Notebook 参数入口与日志：记录真实阶段和逐题预算。
- 候选生成与排序：导出诊断信息，研究增强、去重与第二答案。
- TTT/继续训练入口：支持少量明确的配置变体和恢复权重。

产物为手动运行的 Notebook/脚本、配置、候选输出、训练权重位置和实验记录。大文件不塞进研究文档。
