## 研究背景与明确选择

承接 `003-research-direction.md` 的证据：公开 NVARC 系列约30分上下的提交已经包含逐题微调、增强、DFS 与候选重排；继续调参数未必能突破。Google 新增的500个 ARC2 训练题生成器提供了更直接的数据改进机会。

**第一轮研究问题：在相同训练量与推理预算下，ARC2 新规则合成数据能否让已有网格学生解决更多任务？**

本计划研究 4B 网格学生继续 LoRA，为更强基座提供专用模型对照。本轮不要求从零训练新架构，也不依赖复制试提交的原始代码可访问。

这里的“新数据”首先指2026新增生成器产生的规则变体。底座可能已经看过这些原始规则；500个生成器不等于500种对底座完全陌生的规则。后续的新组合研究负责探查更远的迁移。

## 网格模型的表示边界

**网格模型只有16个token/embedding。** 保留原有数字、分隔符和网格序列化，不换成通用 Qwen chat template，不把自然语言解释、Python 或长思维链直接塞进去。

005 中更强的语言/视觉语言模型保留各自完整词表，不能套用本计划的16-token表示。16-token能完整表示ARC网格，并不证明模型存在某个固定准确率上限。

离线 LoRA 完成后，可合并成一个固定网格 checkpoint，再基于该 checkpoint 为每道新题初始化独立 TTT adapter。不要把上一道题训练后的 adapter 当作下一题的初始状态；离线和逐题两层训练的配置分别记录。

## 数据方案

### 第一轮用最终网格监督

1. 从 ARC-GEN V2 生成新 input/output pairs，或从 arc-steps 的同一 `task_id` 下取样。
2. 把 **同一潜在规则和兼容配置** 的3–4个样本组成一个 episode：2–3个 demonstrations + 1个 query/target；“task_id 相同”是必要线索，不代替规则一致性检查。
3. arc-steps记录本身可能已有不同的`palette`、`background`、`foreground_map`。首轮先选相同配色配置，或在原映射可逆时还原到统一配色，再组episode；这些原字段一并保存。随后新增的颜色映射、旋转在整个episode上保持一致。只对不同原配色再施加同一个新变换，不能自动消除差异。
4. 首轮收集约10K–30K episodes 的小池，按规则族均匀抽取；这是建议规模，不是必须全量训练的目标。
5. 训练混合初始建议：60% ARC2 新episode，30%旧任务回放，10%人工挑选的薄弱类别。若尚无薄弱类别结论，改成70%/30%，不编造难题标签。

每条 episode 至少保存：`episode_id`、`source`、`source_revision`、`family_id`、`ancestor_task_ids`、`generator_seed`、`augmentation`、`train`、`query_input`、`query_output`。程序与 steps 作为可选研究字段，不默认进入网格模型文本。

### 如何增加真正的新规则覆盖

先覆盖对象选择、条件变化、路径、填充、计数、重组等不同规则，再改变尺寸、对象数量和几何位置。普通旋转/换色属于增强，不应记为新规则。

组合任务需研究中间结构是否兼容、示例是否足以确定同一规则。不能机械把任意两个生成器串起来就认作有意义的新题。首轮可先做原生成器，第二轮再人工设计少量明确的双规则组合；保存组合图和父任务ID。

### 保留三个不同的观察集合

- **公开题诊断集**：用于观察模型错误与候选覆盖。NVARC初始化可能训练过公开evaluation，分数只作诊断。
- **续训留出family**：按原任务/生成器分组划分，跨数据集同一task及全部增强归到同组。这衡量本轮新数据的迁移；初始化可能已见过原规则，不能称完全未见。
- **新组合规则留出集**：将完整组合模板及变体一起留出，观察组合迁移；它仍是合成分布，不替代Kaggle隐藏集。

不需要建立专门测试套件。由人工发起数据准备与实验，查看几组网格和输出，记录实际划分即可。

## 第一轮手动对照

先用相同推理配置隔离“训练数据”这一变量。模型输入只含 demonstrations 与 query input；真值仅用于训练目标或运行后的统计，不送给隐藏题求解器。

| 实验 | 改动 | 要回答的问题 |
| --- | --- | --- |
| G0 | 原始专用checkpoint，不做离线续训 | 建立当前代码与任务清单下的对照，不追求复制某个公榜峰值 |
| G1 | 只用旧数据继续LoRA | 增加相同训练量本身是否有影响 |
| G2 | ARC2新数据混合继续LoRA | 与G1匹配训练token预算，观察新增规则是否有价值 |

这三个对照可与005中的新模型研究并行选择，不必同时把全部系统写完。

记录 `exact_match@2`、`oracle@K`（候选里是否出现真解）、二者差距、相对G0新增/丢失的test outputs、生成/排序/TTT耗时和未完成数量。正式指标按 **test output** 求均值；不要照搬参考Notebook可能不同的task平均法。没有真值的隐藏题不能计算oracle。

单次小涨幅不作稳定效果结论。仅对看起来有实质变化的候选再手动重复，优先看新增题是否重复出现；不搭自动跑分门禁，不全量重复每一种配置。

## 第一轮训练起始配置

以下是便于开工的**待验证建议**，不是文献已经证明最优的配置，也不表示保证显存可容纳：

| 项目 | 建议起点 |
| --- | --- |
| 底座与精度 | 专用4B BF16，冻结底座，训练LoRA；先用已有CUDA训练生态 |
| Adapter | attention/MLP线性层；rank64、alpha32、rsLoRA；保留16-token输出结构 |
| 学习率 | 先2e-5；只有结果显示训练不足时再试5e-5，不启动大网格搜索 |
| Batch | 每卡1 episode，梯度累积；按实际可用卡数形成有效batch约8 |
| 序列 | 先处理可完整放入4096的episode，再扩8192；不能截断输出网格，记录超长样本覆盖差异 |
| 显存 | activation checkpointing；先测一张卡上的实际峰值；四卡数据并行不会减少每卡底座占用 |
| 训练量 | 先手动运行几十步测吞吐，再给G1/G2相同约100–300步对应的有效token预算；超过会话预算就缩量 |
| 保存 | 起点、短程中点与终点adapter及完整配置；先保留可恢复的小产物 |

G1/G2尽量匹配有效训练tokens而非只匹配step数，避免长度差异让比较变成不同训练量。首轮保持原TTT和候选参数，不能训练与推理一起修改后仍归因于新数据。

100–300步首先用于可行性与初步学习信号；有效batch约8时只涉及约800–2400个episode，可能不足以覆盖500个family及旧数据。短程没有改善不等于数据方向无效，应结合实际覆盖与学习信号决定是否扩大预算。

LoRA若效果不够，下一步可对小样本试更高rank或局部解冻；全参数分片训练留到有收益证据后再研究。不要把首次实现变成分布式框架开发。

## 后续研究分支

只有第一轮的观察说明值得投入时，再从下面选择一项：

1. **组合规则课程**：生成少量更复杂但语义清楚的新任务族，研究难度混合而非只堆样本数。
2. **中间网格监督**：对相同数据做±steps消融。需设计边界、阶段对齐与最终答案提取；不能训练时喂真值步骤、推理时却假定步骤自动存在。
3. **更强模型适配**：按005比较新初始化模型，避免将旧模型的收益平台误认为任务本身的上限。
4. **效率蒸馏**：4B→更小网格学生，研究节省的时间能否换来更多解题；不是默认越小越好。
5. **DRM/TraceViT复现**：单独立项，先补齐checkpoint/训练实现和实际预算，再决定是否投入。
