# 009 — 有效 episode：无损表示、采样覆盖与示例消歧

日期：2026-10-01。结果见[同名progress](../progress/009-efficient-episodes.md)。承接008已完成的CPU准备；当前不使用Kaggle GPU、不调用模型或付费教师API。研究固定Qwen3.8-27B，不重新选模型。

## 1. 本轮问题

008已经准备评价清单、tokenizer长度统计、2240条新base和训练器入口。本轮继续研究三个GPU之前可回答的问题：

1. 不裁模型词表，仅改变网格字符串，能省多少真实token、保留多少完整任务？
2. 已有长度配比在800条训练量下，究竟覆盖哪些任务和实例？能否在相同token预算下改善？
3. 合成episode的已知示例是否暴露了query需要的规则信息？如何区别标签错误、合理泛化和未约束的任意映射？

目标是减少下一轮昂贵训练中的信息浪费。CPU可验证token数、覆盖、有限假设分歧；不能验证模型准确率、实际L4速度或比赛提分。

## 2. CPU实验设计与实际范围

### F：无损网格表示

固定Qwen3.8 tokenizer revision `1d4bf0f2ff6012fd82039f2fa52739d0dd7c60c0`，比较：原空格数字；每行连续数字无空格；每行`color:count`的游程编码。每种格式都保留全部demo、query与目标，不截断或删格。

数据分别统计：892个训练task的全部962个官方test query；2240个新生成base；120个公共evaluation的172个query题面，其中E24为36query。评价query答案不读取、不下载；只能计算prompt成本，不能冒称完整训练序列成本。

对所有已读网格逐一编码/解码复核，报告每种表示的prompt/target/EOS/full token分布、4K/8K覆盖及最坏长度。手动分析入口 `experiments/009/analyze_serialization.py`，不是训练器或测试套件。

### S：相同长度配比的任务覆盖

继承D2旧3000行索引和008已确认token统计。另建剔除53条不满足当前LOO规则的2947行统计子集；原文件不动。对同一子集比较当前随机长度桶、来源/task/base公平选择、公平选择并优先覆盖无生成器的非ARC1任务。

长度配比固定20/40/40，800行；另外独立比较相同full-token上限。固定首seed20260930，再用预声明的20个连续seed考察覆盖稳定性。报告真实(source,task,base)键，不能把task数当base数。所有选择只是离线模拟；未物化的新2240base不计入旧索引成绩。

### Q：有规则见证的语义审计

只用训练侧新2240base，先查同族同输入不同输出、query直接重复demo、仅输出重复三种现象。对008的6个存疑族读取固定源码并逐输入重建规则，再扩至少量有明确映射信号的族。

有限假设见证必须是短而合理的替代规则，例如未展示的尺寸→颜色映射；不能用为某个query硬编码的恶意函数证明所有episode都有歧义。输入可观察的spacing、对象位置、前景色、计数应允许跨示例变化；不要求demo穷举。

对一个明确欠定episode，保持query/target与demo数不变，用现有同族pair替换冗余demo；记录来源、选择依据、token/网格成本及替代规则数。只产出可审查的原/修复配对，不覆盖原池、不宣称改善模型。

## 3. 本轮结论如何进入下一轮GPU实验

### 3.1 E0历史配对仍保持原格式

008的base/G1配对照原方案进行，保留space格式、2048输出上限。不能把换格式后的结果当作历史G1提升，也不能静默重写E24或备用集合。公开evaluation题面可用于长度统计，query答案仍由以后独立评分读取。

### 3.2 新增轻量F1候选，优先于直接推进G3

F1定义：完整原词表、原embedding/head、原chat控制token；所有网格按连续单数字加换行表示，system说明同步改为无空格。当前tokenizer实测为每个数字一个token，不需要新token ID或权重转换。

GPU阶段先在预先固定的小片做格式能力探针，再决定是否建立F1专项SFT分支。可以给同一离线checkpoint两种格式各一次greedy，观察合法率、exact-match、token数及时间；这只是格式敏感性，不能代表已完成格式适配。

若需要训练比较：F0/F1从同一底座或同一G1初始化，使用相同原始episode和顺序、相同LoRA范围。首先做**同episode预算**，研究表示本身；有价值后再做**同墙钟预算**，研究省下的时间是否能增加实例和解题。token数相同、episode数相同、墙钟相同是不同实验，不能混称公平。

F1输出上限可按最大30×30网格的930token加小余量设置，例如960；这是格式上界，不能读取待答真值尺寸。先在CPU核实实际EOS/换行规则，再在GPU测模型是否合规。RLE暂不作为主线：它可能缩短部分稀疏网格，但最坏长度更大，且引入计数/展开错误。

F1若保持或提高解题、实际用时下降，就考虑作为G2的表示分支；若准确率下降且短程适配不能恢复，继续F0。G3仍保留输出头计算和权重压缩的独立价值，但不再把序列减半的收益全部归功于裁词表。

### 3.3 采样与示例质量

在最终数据物化后重新计量，不直接沿用本轮2947索引的覆盖数字。优先按来源→任务→base选择，保留无生成器非ARC1任务的抽样机会；需通过GPU确定广覆盖与重复练习的折中。

对有具体欠定见证的episode，先保留原/修复两份用于小对照。不能把“仅输出相同”统一删除，也不能把所有query新颜色都删掉。原始随机episode保留一部分，避免训练只见过精心消歧的容易上下文。

下一项数据质量实验应固定family、query、demo数和近似token预算，只比较随机demo与区分性demo。把loss下降、可区分假设数下降和真实exact-match分开记。标签正确不等于训练有效；审计通过也不保证泛化。

本轮只新增009分析脚本、证据和文档，不改用户正在修改的008数据/训练器。以下是后续最小实施需求，不能把本轮分析产物直接当生产训练入口：

| 位置 | 需要衔接的行为 |

| `arc_episode_data.py` | 显式formatter版本；同一模式的grid序列化/解析；统一suspect标记策略；将索引、新base与修复记录物化为messages/target |
