# 021 NVARC 完整流程与 27B 互补研究交接

日期：**2026-10-21，北京时间**。项目审阅基点：`248dabac97b07afe7a4209fc19e1db5b7d4758ee`。接手者先读本文，再读[020低分复盘](../progress/020-score-validation-and-real-submission.md#27-正式公榜1250与低分复盘)。本轮实际完成的调研与产物见[021进展](../progress/021-nvarc-complementarity-handoff.md)。

**建议采用“完整 NVARC 4B 对照 → 相同总时间的 27B 互补 → 一个限时 4B 数据续训挑战者”。** 这与用户提出的方向基本一致，但融合是否值得采用必须由实际两个答案的净收益决定。首要任务是找回可复现的有效求解流程，而非继续原样提交12.50版本，或把27B全面改造成专用网格模型。

本计划只交接研究设计和必要实现。本轮不启动GPU、不训练、不提交比赛、不改变最终提交选择。保留 `Qwen/Qwen3.8-27B` 作为大模型候选；不重开基座选型，不引入SOAR 7B，不建设测试体系或CI。下文的实验配置与时间分配均为**待执行建议**，效果均**未运行**。

## 2 对用户判断的修正与补充

1. **“完整4B＋27B互补最值得投入”成立为优先假设，不是已证实最优解。** 需要三臂比较：完整4B、缩预算4B、缩预算4B＋27B。只有后者超过完整4B，才证明值得把时间给27B。
2. **27B官方42.4%确有其事，但它是ARC2 Semi-Private成绩。** 官方使用Baseten专用推理、xhigh；不是本届Kaggle公榜，也不是120题公开集分数。它支持继续研究能力，不提供L4×4上的分数承诺。[官方结果](https://arcprize.org/results/alibaba-qwen3-8-27b)
3. **109个新增生成器是具体资产，不是109种新发现的规则。** 它们相对固定ARC-GEN增加采样覆盖；NVARC已接触ARC2 training及其他合成数据，不能把这些规则称为底座未见。
4. **“48小时挑战者”须同时约束GPU成本。** 48小时是实施和分析的日历期限，不是允许连续训练48小时；首轮只保留一个训练终点及原版对照，不能同时开DPO、新架构和27B全量专训。
5. **完整NVARC 4B不等于2025整个NVARC参赛系统。** 这里具体指专用4B的表示、TTT、增强、搜索、重评分完整链。上游还有TRM等工作，不能自动把所有分支都列为本轮必须复现的内容。
6. **优先做能保住已有答案的改进。** 27B多query返回中一个成员非法时，当前解析可能丢掉整题；可保留其他已经完整且合法的query。该修改值得低成本核查，但只有新增exact才算收益。

## 5 实验顺序与交接产物

### A 固定并恢复完整4B对照

研究问题：一个源码、权重、依赖均可对应的完整4B流程，在本届输入与预算下实际能覆盖多少、解出多少？

1. 从021已归档V1出发，固定`model=sorokin/qwen3_4b_grids15_sft139/Transformers/bfloat16/1`、原依赖源和许可，记录实际挂载文件SHA与依赖版本。源码已取得；依赖在当前镜像下的可运行性仍需实测，不能继续用014的V2替代。
2. 保留V1的formatter／16-token词表、每题adapter重置、TTT样本、增强、DFS及重评分；修复兼容性所需的修改单独列出。V1未发现独立rescue阶段，不把013或其他版本的rescue附加进来后仍称原版。第一轮不同时调这些环节。
3. 在E20先做一个短块检查实际TTT更新、候选生成、逆变换和两槽产物，然后跑同条件观察。短块只是启动与计量，不凭几道题宣称全量有效。
4. 导出每query的去重候选、原排名与分数、生成/评分时间、每task TTT时间、超时/OOM/零候选。完整真实预测与占位分开计数。
5. 尽早形成一次可计分的完整4B版本；正式隐藏分数才是本届复现证据。不要等训练挑战者完成才保留有效候选，也不要原样重投已知25.69版本。

本轮统一41400秒总时钟比V1原42600秒更保守，须记为预算调整。B0表示“方法完整、使用本轮完整可用时间”的对照，不声称与33.89版本字节和运行条件完全相同；如果最终采用原截止，也要让所有比较臂使用同一时限并重新计量余量。

小题单不能每题独享1200秒后声称全量预算可行。4B四个独立worker的平均可用GPU秒约为`4 × 4B阶段墙钟 / 240`，还须扣除安装、重评分和调度长尾。27B TP4是四卡共同服务，不适用这个每题乘4公式。

### B 三臂比较实际互补

| 臂 | 运行政策 | 回答的问题 |
| --- | --- | --- |
| B0 | 4B使用完整可用求解时间，提交自身top2 | 最强完整4B对照 |
| B1 | 4B只用为融合分配的时间，仍提交自身top2 | 为27B让出时间损失了多少 |
| B2 | 与B1相同4B阶段，余下时间运行27B，冻结规则选最终两槽 | 27B能否补回损失并超过B0 |

B1与B2可共享完全相同的4B候选产物；B0需要自己的完整预算结果。只在任务顺序、随机种子、阶段停止行为等完全一致时，才能从保存的运行前缀构造B1；普通事后删候选不等价于真实缩预算运行。

首轮以E20作为配对开发观察。先得到B0/B1以及预先指定的27B覆盖结果，再离线比较固定槽位规则；不能看到答案后只让27B处理其会答对的题。真实部署路由只能使用示例、输入、4B候选及耗时信息。

**E20的覆盖诊断与部署预算必须分开。** 为了解互补性，可以在研究预算允许时让27B覆盖E20全部20题；该结果只能叫“候选覆盖诊断”。若最终27B只够处理240题中的约24题，比例约10%，E20的部署模拟就只能路由约2题，不能把其余18题的27B答案并入B2。如此小的路由样本只够初步观察，不能据0/2或1/2断言互补是否有效。

随后在更大的冻结公开块、尽可能完整的120task输入上运行路由：固定比例上限、预计token/时间总额和停止策略，报告`被路由task数 / 全部task数`及对应query数。小片可用`阶段生成预算 × n/240`近似分配工作量，安装/加载单列为实际成本；该缩放忽略batch填充、prefill和长尾，仅是研究近似。必须保留同硬件端到端演练及真实提交记录，不能用缩放结果证明12小时全量可行。正式N、Q变化时根据真实输入数量重算公平份额。

**首版选槽只保留两种简单政策：**

- 全部保留4B的第一候选；被路由且27B产生不同合法网格的query，用27B替换第二槽，否则保留4B第二槽。
- 在上述政策上增加一条预先固定的4B候选一致性条件，观察减少替换是否改善净收益。阈值只在开发块设定，冻结后再扩展观察。

不能直接混排4B增强似然、27B自评置信度、程序demo准确率。它们不在同一量纲。保护第一槽也不能保证不退分，必须统计被挤掉的第二槽独有正确答案。重复网格不因来源不同就获得两个独立机会；没有替代候选时允许重复，但如实记为单一预测。

至少报告以下逐query计数，汇总为`query-ledger.jsonl`和一张结果表：

- B0、B1、B2的EM@2，及task全部query命中率；失败/超时/占位均留在分母。
- `new`：B2正确而B0错误；`lost`：B0正确而B2错误；净变化为`new − lost`。
- B1相对B0的损失，B2相对B1的增益，以及被替换的4B第二槽独有命中。
- 合法预测率、两槽不同率、每来源的独有命中、总墙钟、总token、最后一批未完成量。
- 所有候选并集oracle与实际两槽之差；oracle只说明选择潜力，不能作为可提交成绩。

依据新增/损失、实际路由样本量、成本和剩余额度决定是否扩大冻结策略观察及安排计分；**不设“净增2query且跨2task”的硬门槛**，继承020中用户已要求取消该限制的决定。少量新增可以支持一次限额计分探索，但不能宣称稳定增益；极小路由样本的零净增写“证据不足”。已有较充分配对证据仍无收益时，B0作为当前提交候选，停止原配置扩算，不靠oracle掩盖实际无增益。若B0本身异常低，先定位完整流程复现问题，不解释为27B一定更强。

### C 27B只处理有价值的剩余工作

保留020已运行的FP8权重、TP4／C8及实际MTP2服务配置作为起点；先不切双TP2、不换运行时、不把3090吞吐搬到L4。C8是并发请求数，不是八倍单请求速度。每task一次请求可同时处理其全部query，保留每query独立状态。

优先核查两项低成本改动：

1. 合法完整JSON对象中，逐query保留完整合法网格，明确记录缺失、重复key、非法值；不猜测补齐截断数组，不从分析文字随意抽数字当答案。
2. 安装、挂载、启动失败明确非零退出，保存已有结果和错误。若融合阶段27B失败且4B已有完整产物，可结束为“4B有效、27B失败”的可诊断回退；不能把全占位写成正常模型完成。

推理深度首轮不再做全题无条件49K。先保留xhigh，在相同总体预算下观察一种较短上限与当前长上限的“新增解/时间”，优先覆盖已选任务再给第二次机会。不得把低effort等同于更好效率。已知不能交付的长分析，只有在看见短收尾可能恢复真实答案时才做一次限额对照；016的合法率改善不能视为本轮已经有效。

路由最初使用少量可解释特征：4B是否无候选、候选分歧/排名差距、输入及输出规模、预计27B成本。**低置信度不等于高互补性。** 保留一小部分其他置信区间的观察，避免全部预算流向两个模型都不会的最难题。不在20题上训练复杂router，不使用任务ID白名单或答案引导的路由。

### D 唯一的限时续训挑战者

研究问题：额外生成器提供的结构变体，能否在保留旧分布的情况下增加完整TTT流程的真实query命中？此项排在A/B之后；A/B尚无可用候选时，训练不抢主线配额。

固定数据源：ARC-GEN `a15cbdb44c776610aeeb9f487a06af875d3d0878`；Re-ARC2 `d9ea8b2fc21ac4189f1a895aaeef84cf74df16b0`。Re-ARC2的training-minus-ARC1清单609个ID与ARC-GEN的900任务文件相交500，差集109。本轮已复算，并确认109/109个generator及verifier文件存在，详见[完整ID与方法](../../experiments/021/evidence/rearc2-generator-delta.json)；没有运行生成器或验证质量。差集是**相对该版本的生成器覆盖**，不是新任务/规则发现数量。[ARC-GEN固定版本](https://github.com/google/ARC-GEN/tree/a15cbdb44c776610aeeb9f487a06af875d3d0878/tasks)、[Re-ARC2固定清单](https://github.com/water-vapor/synth-rearc/blob/d9ea8b2fc21ac4189f1a895aaeef84cf74df16b0/data/task_lists/arc2_training_minus_arc1_task_ids.txt)

第一版只设一个混合：约50%新增109覆盖、50%旧training来源回放，按family均衡抽样并记录有效token比例；若只有少数可靠新增family，先缩范围，不为凑109放入未核材料。留出按祖先task/family分组，同family不同随机种子只能叫实例留出。所有query目标只参与离线监督，正式TTT只能使用当前题demonstrations，不能读取query答案。

## 6 12小时提交如何分配

默认先运行4B四个独立worker，持久化全部已有答案；结束并释放4B后，再启动27B TP4处理路由队列。先后运行减少四卡争用，且27B失败时可保留4B产物。两套依赖宜复用各自已验证环境/子进程，不在同一个Python进程中反复覆盖Torch及Transformers。

总预算必须满足：

`4B安装加载 + 4B逐题TTT/搜索/重评分 + 卸载切换 + 27B安装加载/推理 + 最终写出 ≤ 41400秒`。

平台上限为43200秒，留1800秒外层余量。第一cell启动统一时钟，最后600秒停新请求，最后300秒终止未完成生成并汇总。终止/收尾必须实际可打断，不能只轮询时间。

可测的初始情景是**8小时4B求解＋2小时27B求解＋1小时累计安装切换＋0.5小时收尾**，总11.5小时；这不是推荐的固定最优比例。若8小时显著损失4B能力，改回更长4B或纯4B，不强行维持混合。先导测完才固定阶段截止。

27B按本项目约130—141 completion token/s的既往聚合吞吐计算，2小时只约94万—102万token；若每task约4万token，仅够约23—25task，尚未扣长输入prefill与长尾。这是条件测算，表明27B应精挑一小部分任务，不能说“剩两小时再全量跑27B”。实际批处理吞吐、首token延迟、输出长度分布、取消尾部均须计量。

B0和B2比较的是同一硬件、同一端到端时限。分开研究会话各自跑满后合并，只能测互补潜力，不能宣称得到12小时提交方案。所有全量预算估算要同时给实际N/Q、任务大小分层和已完成比例，不只报平均token/s或GPU忙碌率。

## 9 接手者第一天直接做什么

1. 读020复盘与本文；重查配额、正式规则/截止，不重做模型选型。
2. 使用021已归档完整4B参照和版本身份，检查014本地V2的误用风险；只做必要离线兼容修改。
3. 用E20的预先固定小块测TTT、搜索和每query产物，再确定符合240task负载的B0/B1时间强度。
4. 从现有27B产物先做CPU解析回放，确定逐query保留是否实际新增合法预测；有需要才开新GPU观察。
5. 输出一张B0/B1/B2待填表及实际预算安排。先证明融合净收益，再决定D是否值得占用剩余时间。

若只能交付一个改进，应优先得到一份**有确切版本、完整流程、实际计分和逐query诊断的4B候选**；若还能多做一个实验，应回答**27B新增命中能否抵消让预算和替换第二槽的损失**。这两项比同时扩展多条未经验证的后训练路线更有机会在剩余时间形成可提交收益。
