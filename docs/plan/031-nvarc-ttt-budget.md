# 031 原NVARC TTT预算小对照

## 背景与唯一假设

2026-10-27用户要求继续研究并尽快做实际提分submission。030的DFS0.1在20task／28query同预算系统对照中6→6，新增2／丢失2；该配方已结束。本轮不扫描阈值、不复活027融合、026权重或028／029 runtime支线，保留023正式30.14。

新假设：原128步逐题TTT的后半段成本可能超过其候选质量收益。保留原128样本、1epoch学习率调度及原DFS0.2／B4，在64步停止TTT，检验节省的时间能否保住正确候选并增加搜索覆盖。没有现成的64步提分证据，这是一项可否证的小规模研究，不把训练损失或代码完成当成提分。

本地依据：原V1 `312063593` 的 `train_args` 与 `trainer.train()`；030 base已闭合TTT／DFS／重评分host工作和3654.934／6095.607／820.352秒。这里的工作和不是CUDA profile或墙钟关键路径，不能推导总速度翻倍。

## 固定干预

- 原sft139 BF16 V1、rank256 rsLoRA、训练增强n16 seed1、Trainer／PEFT seed42、搜索增强n2 seed2、四GPU原排序队列、540秒DFS／1200秒task软检查不变。
- A为原128步TTT；B在原完整训练数据与128步cosine调度下，由 `TrainerCallback.on_step_end` 在global_step64停止。禁止将 `max_steps` 设64、将增强改n8或重算64步scheduler；实际max_steps／步数／LR必须从日志核实。
- DFS累计概率门槛固定0.2，原全部四批搜索、8视角重评分、B4最终两槽不变；不加入融合、候选替换或新seed。两臂共同hash27031。
- 两臂独立训练，数值路径可能不同；030已有相同配方TTT字节指纹不一致证据，不能把这次称为同adapter纯因果消融。

## 预定判据

先冻结两臂预测、原始／重评分候选、顺序与工件身份，再读取固定官方快照评分。满足以下条件才尝试提交相同V1：

1. 完整12query最终EM@2净增严格为正；不因未搜索而缩小分母。
2. 本次A在2ba必须复现正确答案仅在第二槽，B须仍然正确；否则已知第二槽风险未覆盖，不直接晋级。
3. B获得搜索的query数及完成搜索batch数均不少于A。若两臂都完成全部搜索，只能报告候选质量／耗时变化，不能宣称本面板额外覆盖。
4. 实际TTT步骤／scheduler、输入身份、模型字节、原B4重放、时限及完整输出通过人工核查；运行错误不当算法失败处理，预设预算截断可以纳入完整分母系统对照。

小面板净增只是一次有风险的正式尝试依据，不是公榜必涨或金牌预测。零／负、风险检查失败或覆盖下降即结束64步配方，不在本面板扫描32／96步、改LR／seed／排序救结果。不提交失败配方，不为消耗每日名额而重提023。若通过，精确绑定V1／实际scriptVersionId／submission.json，以Kaggle CLI正式提交；实际公榜超过30.14才称正式提分。
